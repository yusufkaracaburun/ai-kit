# Accessibility (WCAG 2.2 AA)

Every user-facing UI ships at WCAG 2.2 AA. Accessibility is a correctness
property, not a polish item — broken a11y means broken software for ~15%
of users.

## Hard rules

- **Semantic HTML first.** `<button>` for buttons, `<a href>` for navigation,
  `<form>` for forms. Custom `<div role="button">` only when no native
  element fits.
- **Keyboard reachable.** Every interactive control must be tab-reachable,
  operable with Enter/Space, and visibly focused. No keyboard trap.
- **Labels on every input.** Visible `<label for>`, `aria-label`, or
  `aria-labelledby` — never a placeholder as the only label.
- **Color contrast** — text 4.5:1 minimum (3:1 for large text). Don't use
  color as the **only** signal (also use icon, text, or pattern).
- **Alt text on meaningful images.** Decorative images get `alt=""`.
- **Focus order matches visual order.** No `tabindex > 0`. Manage focus
  explicitly on route changes and after modals open/close.
- **Live regions** — announce async state changes (toasts, errors, loading)
  via `aria-live="polite"` or status containers.

## Test discipline

- Run `axe-core` (or `@axe-core/playwright`) in E2E on every critical flow.
  Zero violations on merge.
- Manual keyboard-only walkthrough on every new screen — Tab, Shift+Tab,
  Enter, Esc must do the obvious thing.
- Screen-reader spot check (VoiceOver on macOS, NVDA on Windows) on
  non-trivial components.

## Anti-patterns

- "Add aria-labels later" — labels added retroactively miss context.
- `onClick` on a `<div>` without keyboard handler or role.
- Disabling controls without explaining why (use `aria-disabled` + helper text).
- Animations / autoplay video without a way to pause; missing
  `prefers-reduced-motion` honor.
