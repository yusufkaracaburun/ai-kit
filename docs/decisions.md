# Decisions

- 2026-11-16: Heavy runs are serialised by a wrapper, `ai-kit-heavy-run.sh <cmd>`, that takes an atomic `mkdir` lock at `~/.config/ai-kit/heavy-run.lock/` (holder file with PID, repo, command) and releases it with a trap; a lock whose PID is dead counts as free. A PreToolUse Bash hook denies bare heavy commands and points to the wrapper. A hook alone races because it exits before the command starts. (source: grill #288 + #275)
- 2026-11-16: When the lock is held, the wrapper refuses at once with exit 75 and names the holder; it does not wait. (source: grill #288 + #275) Superseded 2026-11-21, see below.
- 2026-11-21: When the lock is held, the wrapper polls every 2 s for up to `AI_KIT_HEAVY_WAIT` seconds (default 600, `0` keeps the old refuse-at-once), printing one waiting line that names the holder; past the limit it exits 75 as before. No FIFO queue. A repo re-running its suite back-to-back starved short runs elsewhere. (source: user decision, heavy-run wait)
- 2026-11-16: Heavy means full suites: pest, paratest, phpunit, vitest, jest, playwright, patrol, maestro, xcodebuild, gradle, plus the aliases npm/pnpm/yarn/bun [run] test, composer test, php artisan test. A run with --filter, -t, or a test-file path stays free. (source: grill #288 + #275)
- 2026-11-16: No override. Hooks fire only on Claude's Bash calls, so the user runs a suite in their own terminal or with `!`. (source: grill #288 + #275)
- 2026-11-16: #275 and #288 ship as one slice, Claude Code only; Cursor and Codex follow later, as review-gate did. (source: grill #288 + #275)
- 2026-11-16: heavy-run-gate is not marker-gated, unlike ADR-0018's hooks: the lock is machine-wide, so every repo with the plugin takes it. (source: review #288 + #275)
- 2026-11-21: A should-i-use test is one real task in the consuming repo, in a worktree there, with one metric chosen before the run, compared against today's way (baseline). README text, vendor benchmarks and "looks like X" are not evidence; they only decide whether a test is worth running. (source: should-i-use grill, #300)
- 2026-11-21: Vendor, Wire and Adopt-as-pattern only with a trial; without one the verdict is Trial, a plan naming repo, task, metric, baseline and cost. (source: should-i-use grill, #300)
- 2026-11-21: Ignore without a trial only on hard facts: license, abandoned, wrong platform, security. Ignore for "redundant" or "no added value" is a claim and needs a trial. (source: should-i-use grill, #300)
- 2026-11-21: The `/ai:dedupe` ecosystem check runs before any verdict. A candidate that does what one of our own skills or scripts does, with a trial at least as good, gets "Adopt and delete ours". (source: should-i-use grill, #300)
- 2026-11-21: The verdict has a mandatory Trial block (repo, task, metric, baseline, result, date, re-measure date); a suite test fails on a Vendor, Wire or Adopt ledger record without trial fields; existing records are marked `legacy, unmeasured` once. (source: should-i-use grill, #300)
- 2026-11-21: Every Adopt gets a re-measure 14 days later through a to-prd Defer issue with the usage metric (post-skill-log Skill calls or the tool's own log); 0 uses means add a nudge or reverse the verdict. (source: should-i-use grill, #300)
- 2026-11-21: Trial budget is one real task and one agent run (builder or designer) without asking, following the one-heavy-run rule; above that (several runs, paid API, machine-wide install, device or simulator) the verdict is Trial with a cost estimate and the user decides. (source: should-i-use grill, #300)
- 2026-11-22: #303 pilot is built by the pilot app's own session in its own repo. ai-kit changes nothing until one real deploy has used it. (source: grill #303)
- 2026-11-22: Deploy ledger is a REVISION file written per release by the app's deploy script (live truth, survives rollback), plus an annotated git tag deploy/<date>-<sha>, set only after a green smoke. (source: grill #303)
- 2026-11-22: Rollback stays a manual symlink switch to the previous release. The rollback line is written in the app's docs. No automatic rollback, because migrations have already run. (source: grill #303)
- 2026-11-22: Changelog is the squash-commit subjects between the previous deploy tag and the new SHA (git log). No git cliff, no model rewrite, customer notes out of scope. (source: grill #303)
- 2026-11-22: The changelog is stored as the annotated deploy tag message. No CHANGELOG.md, so no post-deploy commit. (source: grill #303)
- 2026-11-22: The deploy logic lives in a versioned script in the app repo. The deploy shell function becomes a one-line call to it. (source: grill #303)
- 2026-11-22: The pilot is done after one real deploy of the pilot app with REVISION, a deploy tag carrying the commit list, and the rollback line in docs. Then /ai:harvest as a rule, not a kit script. (source: grill #303)
- 2026-11-22: /ai:next reads priority from the issue's Priority field and status from the GitHub Projects item, with no board config in .ai-kit-setup. (source: grill #313)
- 2026-11-22: The Priority issue field wins over P labels; P labels stay as the fallback for repos without a board. Urgent = P0, High = P1, Medium = P2, Low = P3. (source: grill #313)
- 2026-11-22: Status Doing scores like status:in-progress and Next like ready-for-agent; Blocked and Done items leave the /ai:next list. (source: grill #313)
- 2026-11-22: Issue types: Feature for an epic, PRD or new functionality, Bug for a fault, Task for a slice or chore. (source: grill #313)
- 2026-11-22: #313 ships in two slices: /ai:next reads the fields first, then to-issues, to-prd and triage set the issue type and Priority field and the templates and DoR check accept the field. Recording the board in .ai-kit-setup is dropped. (source: grill #313)
- 2026-11-22: New issues reach the board through the kit: to-issues, to-prd and triage add them to the project that the repo's open issues are on. (source: grill #313)
- 2026-11-22: A new issue inherits Priority from its parent PRD or epic, otherwise Medium. (source: grill #313)
- 2026-11-22: Without a Priority field or issue types the kit skips that part with one message and sets the P label instead. (source: grill #313)
- 2026-11-22: Slice 2 splits into 2a (set type, Priority and board on create) and 2b (templates, DoR check, auto-promote and label seeding accept the field). (source: grill #313)
- 2026-11-22: Board columns map to kit labels: Backlog for needs-triage and triaged work, Next for ready-for-agent and ready-for-human, Doing for status:in-progress or a linked PR, Blocked for needs-info or a "Blocked by:" line, Done for closed issues including wontfix. The column is where the work is; the label says who picks it up. (source: grill #313)
- 2026-11-22: When /ai:triage moves a card it removes labels that clash with the column, and /ai:next prints one warning per card whose column and label clash (for example Doing with needs-triage); nothing blocks. (source: grill #313)
- 2026-11-22: The DoR check passes with the Priority issue field or a P label. (source: grill #313)
- 2026-11-22: In repos with a board the kit stops seeding and relying on status:in-progress and P labels; the Doing column and the Priority field are the source. Repos without a board keep both labels. (source: grill #313)
- 2026-11-22: ai-kit-issue-meta.sh --status moves the card on the derived board and then removes labels that clash with the column in one label write: Backlog drops needs-info, ready-for-agent, ready-for-human and status:in-progress; Next and Done drop needs-triage, needs-info and status:in-progress; Doing drops needs-triage and needs-info; Blocked drops status:in-progress. (source: grill #313)
- 2026-11-22: In repos with a board the kit never sets status:in-progress; the Doing column is the source, and /ai:next still reads both. (source: grill #313)
- 2026-11-22: Ship checks after the merge that the issue is closed and its card is Done; an epic-branch merge closes the issue with a comment linking the PR; refs #N slices stay open. (source: grill #313)
- 2026-11-22: ready-for-agent and ready-for-human say who picks an issue up, not when; --status Backlog keeps them (source: user, after a board cleanup)
- 2026-11-22: #171 ships as three PRs: (1) bootstrap writes universal rules per repo only without a global channel, (2) docs scaffold trimmed, (3) /ai:upgrade removes old universal copies. Cleanup ships last. (source: grill #171)
- 2026-11-22: With a global channel, bootstrap emits only stack rules into .claude/rules. Universal rules are emitted per repo only when global_channel_available is false or the no-global-rules opt-out is set. (source: grill #171)
- 2026-11-22: Cursor keeps the full .mdc set per repo, only when .cursor/ exists before bootstrap, because Cursor has no global rules channel. (source: grill #171)
- 2026-11-22: Bootstrap writes only the docs files a skill reads: docs/agents/triage-labels.md and docs/agents/workflow.md. ADR-template.md and wiki/README.md are dropped; CONTEXT.md is created lazily by grill-with-docs. No setup question and no docs_scaffold marker field. (source: grill #171)
- 2026-11-22: /ai:upgrade removes a per-repo universal rule copy only when it matches a released version of that rule. The plugin ships a checksum list of every released rule version. Copies that match none are kept and listed in the upgrade output. (source: grill #171)
