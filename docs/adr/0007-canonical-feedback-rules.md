# ADR-0007: Canonical feedback-rules layer

## Status

Accepted (Unreleased)

## Context

Issue [#30](https://github.com/yusufkaracaburun/ai-kit/issues/30):
naschool's `.agents/memory/feedback/` had accumulated ~35 project-local
feedback-memories over months, roughly half of which were
agent-/workflow-general rules that any new project would want on day 1
of `/ai:setup`. Every new project was re-discovering these rules
incident-by-incident.

Three mechanisms were on the table for shipping these as a shared layer:

- **A.** Canonical rules under `standards/rules/…/*.mini.md`, emitted
  by `bin/emit-rules.sh`, surfaced by `/ai:recommend-rules`.
- **B.** Auto-included `@-import` in the project-local memory-index
  generated by `/ai:setup`.
- **C.** New skill `feedback-rules` that surfaces rules contextually
  (before-commit, on-AskUserQuestion, writing-tests).

## Decision

**Adopt mechanism A: canonical feedback-rules as `.mini.md` files
under `standards/rules/feedback/`, with `universal: true` so
`/ai:setup` Bootstrap (Branch 1) emits them by default.**

### Why A over B and C

- **A reuses existing infrastructure.** `bin/emit-rules.sh`,
  `bin/lib/recommend-lib.sh`, the universal-flag default-on selection,
  the per-agent emitters (Cursor / Claude Code / generic), and the
  `/ai:recommend-rules` scoring layer all already exist. Zero new
  primitives required.
- **B couples to the memory-index format.** Adds friction every time
  the memory-index format changes (it has changed twice since the
  layer was introduced). Less reuse, more coupling.
- **C adds skill-invocation overhead.** Feedback rules describe
  always-applicable workflow / style / tool-gotcha defaults, not
  conditional behaviour that needs a trigger. An always-on rule loaded
  into the agent's context outperforms a skill that has to be invoked,
  remembered, and re-loaded.

### Layout: subdir, not flat-tag

Feedback rules live under `standards/rules/feedback/*.mini.md`, not
flat alongside canonical rules with a frontmatter tag. Rationale:

- Precedent exists: `standards/rules/external/` already hosts non-
  canonical / per-stack catalog rules (e.g. `laravel-php-83.mini.md`).
- Grouping makes the bucket scannable from disk and from
  `/ai:recommend-rules` output.
- Promotion path is obvious: future cross-project rules drop into
  the same directory; project-local rules stay in
  `.agents/memory/feedback/`.

### Universal by default

All v1 rules ship with `universal: true`. The curated set is
project-agnostic by construction (the harvest criterion), so per-stack
scoring adds friction without gain. If a future feedback rule turns
out to be framework-specific, flip its `universal` flag and let
`/ai:recommend-rules` score it.

### v1 rule set (8 rules)

| Rule | Weight | Type |
|---|---|---|
| `phase-scope-discipline` | high | workflow |
| `branch-cleanup-after-merge` | medium | workflow |
| `deployment-on-demand` | high | workflow |
| `minimal-comments` | medium | style |
| `latest-stable-deps` | medium | style (phase-aware) |
| `mark-recommended-option` | high | UX |
| `bsd-sed-word-boundary` | medium | tool gotcha |
| `gitignore-public-assets-trap` | medium | tool gotcha |

`latest-stable-deps` is universal but its body defers to
[`project-lifecycle`](../../standards/rules/project-lifecycle.mini.md)
— production-phase projects pair the bump with a migration plan.

### Promotion workflow

Manual for now: a generalisable feedback-memory observed in a project
is captured in `~/.claude/ai-kit-lessons.md`, then filed as a GH issue
on `yusufkaracaburun/ai-kit`, then curated into a `.mini.md` under
`standards/rules/feedback/` during the next release. This is the same
flow that produced #29 (domain-model-first) and #30 (this ADR).

Automate (skill `/ai:promote-feedback`) only when the promotion rate
exceeds ~1 / month — premature automation otherwise.

## Consequences

### Positive

- Every new `/ai:setup` Bootstrap run inherits 8 cross-project workflow
  / style / gotcha defaults without extra prompts.
- The promotion path is documented and reproducible.
- Project-local `.agents/memory/feedback/` continues to exist for
  project-specific additions — no migration cost.

### Negative / trade-offs

- The `bin/emit-rules.sh` discovery globs (and the matching ones in
  `bin/lib/recommend-lib.sh`, `bin/ai-kit-audit-ecosystem.sh`,
  `bin/ai-kit-dedupe.sh`) have to be extended to scan
  `standards/rules/feedback/` alongside the flat directory. Done as
  part of landing this ADR.
- Eight more rules in the universal default-on bucket increases the
  active-rules surface for every project. Mitigated by keeping
  feedback rules short (~30-80 lines each) and one-axis-per-rule.

### Reversibility

Trivially reversible: revert the four glob extensions and remove the
`standards/rules/feedback/` directory. Active-rules files are
re-emitted on every `/ai:setup`, so no project state drifts.
